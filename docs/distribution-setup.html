مشهد (Mashhad) — Auto-update & Distribution

How new versions reach users, the one-time setup, and the per-release runbook.

Model: the source repo stays private, but the compiled installers + update metadata are served from a public channel so the app (and Homebrew) can fetch updates with no credentials. Publishing binaries does not expose the private repo. (An Electron installer's app.asar is extractable by any user regardless — this hides the repo, not the shipped JS.)

How updates reach each platform

PlatformMechanismNotes
Windows (NSIS .exe)In-app auto-update (electron-updater) One-click "restart to update". SmartScreen warning while unsigned.
Linux AppImageIn-app auto-update Works only when run as a real AppImage (the APPIMAGE env var is set).
Linux .debNone (apt / manual) The in-app updater is disabled; update via your package manager or a new .deb.
macOSHomebrew Cask brew upgrade --cask mashhad. No in-app updater (that needs Apple signing).

The in-app updater checks the feed on launch, downloads in the background, and shows an Arabic banner with an «أعد التشغيل للتحديث» (Restart to update) button. It is a no-op in development and on unsupported targets.

The update feed

The feed is a public GitLab generic Package Registry in a separate mashhad-releases project, at a fixed latest slot. The app is pointed at it via build.publish in package.json:

https://gitlab.com/api/v4/projects/abdu.medhat94%2Fmashhad-releases/packages/generic/mashhad/latest

electron-updater reads …/latest/latest.yml (or latest-linux.yml) and pulls the installer listed beside it. Each publish also uploads a version-pinned copy (…/<version>/…) that the Homebrew cask points at.

One-time setup do these first — nothing updates until they're done

  1. Make the source repo private. smooth-screen-record → Settings → General → Visibility, project features, permissions → Project visibility → Private.
  2. Create a public releases project. A new GitLab project abdu.medhat94/mashhad-releases, visibility Public. It can be empty — the generic Package Registry needs no commits.
  3. Create the Homebrew tap repo. A new public repo abdu.medhat94/homebrew-mashhad (the homebrew- prefix is required). Push the contents of the homebrew-mashhad/ folder from this repo into it.
  4. Add the publish token. In the source repo, Settings → CI/CD → Variables, add RELEASES_TOKEN (masked, protected) — a Project/Group Access Token or PAT with api scope and write access to mashhad-releases. The CI job and the local publish script both use it.
  5. Publish a first release. Clients can only update from something already on the feed — see the runbook below.

Releasing a new version

Bump the version first so the tag, latest.yml, and the Homebrew cask all match:

# 1) bump "version" in package.json (e.g. 0.1.0 -> 0.1.1), commit, and tag
git commit -am "release 0.1.1"
git tag v0.1.1 && git push && git push --tags

Windows (built & published locally — no Windows CI runner)

npm run dist:win                         # builds dist/Mashhad-<version>-x64.exe + latest.yml
RELEASES_TOKEN=<token> npm run publish    # uploads exe + blockmap + latest.yml to the feed

Linux (automatic on the pushed tag)

The build:linux CI job builds the AppImage/.deb and runs npm run publish for you (using RELEASES_TOKEN). Nothing to do beyond pushing the tag.

macOS (on a Mac — can't be cross-built)

npm run dist:mac                         # dist/Mashhad-<version>-arm64.dmg (+ .zip)
RELEASES_TOKEN=<token> npm run publish
shasum -a 256 dist/Mashhad-<version>-arm64.dmg   # copy the hash

Then in homebrew-mashhad/Casks/mashhad.rb set version and sha256, commit, and push the tap.

Verify an update end-to-end: install an older version than what's on the feed, launch it → the banner should appear, download, and the restart button installs the new build. Confirm the feed is reachable: open …/mashhad/latest/latest.yml in a browser (should download/show).

How users install & update

Windows

Download and run Mashhad-<version>-x64.exe. Updates apply automatically in-app (banner → Restart to update).

Linux

chmod +x Mashhad-<version>-x86_64.AppImage && ./Mashhad-<version>-x86_64.AppImage

AppImage updates in-app. For the .deb, reinstall the newer package.

macOS (Homebrew)

brew tap abdu.medhat94/mashhad https://gitlab.com/abdu.medhat94/homebrew-mashhad.git
brew install --cask mashhad     # install
brew upgrade --cask mashhad     # update

Notes & caveats

  • unsigned Windows shows a SmartScreen prompt; macOS is Gatekeeper-quarantined (the cask clears the quarantine flag automatically). Real signing/notarization is a separate, later step.
  • Versions must stay in lock-step: package.json version = git tag = filename = Homebrew cask version.
  • The build scripts run electron-builder … -p never — they generate latest.yml but never upload; uploading is done only by scripts/publish-release.js.
  • The repo has been public in the past, so treat any previously committed secret as exposed and rotate it.
