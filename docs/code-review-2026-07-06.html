Remediation roadmap

Suggested sequencing rather than a mandate — quick, high-impact fixes first, then the performance work that scales with recording/project length, then the structural editor.js split that the duplication findings above all point toward.

Phase 1 — Stop the data loss

Small, isolated fixes. Do these first.

  • Guard the recording state machine — add an arming/stopping check in startRecording/toggleRecord and a session guard in rec:start (#1, #2).
  • Make zoom-block edits undoable and dirty-tracked — the app's signature feature currently isn't (#3).
  • Add a timeout to resolveDuration() — one line, matches its three siblings (#5).
  • Add onerror handlers to both MediaRecorders and an ended listener on the capture track (#6, #7).

Phase 2 — Scale with recording length

These get worse as recordings/projects grow, which is the app's core use case.

  • Stop keeping full-length decoded PCM in memory — stream or downsample for waveform peaks and silence detection (#4, #18).
  • Cache editedStartOf/editedDuration with incremental invalidation instead of recomputing per frame and per rebuild (#8, #15, #29).
  • Stop rebuilding the whole timeline DOM on every edit — diff instead of innerHTML = '' (#9).
  • Stream the export buffer to disk instead of one IPC message + a blocking writeFileSync (#10).

Phase 3 — Split editor.js

3,496 lines, ~10 separable responsibilities. The duplication findings are symptoms of this.

  • Natural module boundaries: playback engine, timeline render, drag/interaction, clip/edited-time model, project persistence, undo, track ops, audio analysis, export.
  • Collapse the four duration-resolvers, the audio/overlay track-lane pairs, and the cover-fit math into shared helpers as part of the same pass (#23, #25, #53).
  • Same treatment applies at smaller scale to ffmpeg-export.js's exportVideo (#24).
